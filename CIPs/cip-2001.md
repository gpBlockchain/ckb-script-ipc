# CIP-2001: Standard Key-Value Storage Service Interface

| CIP | 2001 |
|-----|------|
| Title | Standard Key-Value Storage Service Interface |
| Author | CKB Script IPC Team |
| Status | Draft |
| Type | Standards Track |
| Category | Interface |
| Created | 2026-02-06 |
| Requires | CIP-0001 |

## Abstract

This CIP defines a standard interface for key-value storage services in CKB scripts via IPC. It specifies a common set of storage operations including get, set, delete, and iteration that enables scripts to persist and retrieve data through a shared storage service. This allows multiple scripts to share a common storage backend while maintaining isolation through namespaces.

## Motivation

CKB scripts often need to store and retrieve data during execution. Currently, each script must implement its own storage logic, leading to:

1. **Code Duplication**: Every script that needs storage must implement similar logic
2. **Inconsistent Interfaces**: Different scripts use different storage patterns, making interoperability difficult
3. **Resource Inefficiency**: Multiple storage implementations consume more on-chain resources
4. **Complexity**: Managing state across script executions requires careful implementation

By defining a standard key-value storage service interface:

1. **Code Reuse**: Scripts can share a single storage service implementation
2. **Interoperability**: Different scripts can use consistent storage patterns
3. **Namespace Isolation**: Multiple scripts can safely share a storage service with proper isolation
4. **Flexibility**: The storage backend can be swapped without modifying dependent scripts

## Specification

### Service Trait Definition

The storage service MUST be defined using the `ckb_script_ipc::service` macro:

```rust
#[ckb_script_ipc::service]
pub trait KvStorage {
    // Basic operations
    fn get(namespace: Vec<u8>, key: Vec<u8>) -> Result<Option<Vec<u8>>, StorageError>;
    fn set(namespace: Vec<u8>, key: Vec<u8>, value: Vec<u8>) -> Result<(), StorageError>;
    fn delete(namespace: Vec<u8>, key: Vec<u8>) -> Result<bool, StorageError>;
    fn exists(namespace: Vec<u8>, key: Vec<u8>) -> Result<bool, StorageError>;
    
    // Batch operations
    fn batch_get(namespace: Vec<u8>, keys: Vec<Vec<u8>>) -> Result<Vec<Option<Vec<u8>>>, StorageError>;
    fn batch_set(namespace: Vec<u8>, entries: Vec<KeyValue>) -> Result<(), StorageError>;
    fn batch_delete(namespace: Vec<u8>, keys: Vec<Vec<u8>>) -> Result<u32, StorageError>;
    
    // Iteration
    fn iter_keys(namespace: Vec<u8>, prefix: Vec<u8>, limit: u32) -> Result<Vec<Vec<u8>>, StorageError>;
    fn iter_values(namespace: Vec<u8>, prefix: Vec<u8>, limit: u32) -> Result<Vec<Vec<u8>>, StorageError>;
    fn iter_entries(namespace: Vec<u8>, prefix: Vec<u8>, limit: u32) -> Result<Vec<KeyValue>, StorageError>;
    
    // Namespace management
    fn clear_namespace(namespace: Vec<u8>) -> Result<u32, StorageError>;
    fn namespace_size(namespace: Vec<u8>) -> Result<u64, StorageError>;
}
```

### Data Types

#### KeyValue

A key-value pair structure for batch operations:

```rust
#[derive(Clone, Serialize, Deserialize, Debug, PartialEq)]
pub struct KeyValue {
    pub key: Vec<u8>,
    pub value: Vec<u8>,
}
```

#### StorageError

Error types that can be returned by storage operations:

```rust
#[derive(Debug, Clone, Serialize, Deserialize, PartialEq)]
pub enum StorageError {
    /// The key exceeds the maximum allowed length
    KeyTooLarge,
    /// The value exceeds the maximum allowed length
    ValueTooLarge,
    /// The namespace exceeds the maximum allowed length
    NamespaceTooLarge,
    /// The storage capacity has been exceeded
    StorageFull,
    /// The batch size exceeds the maximum allowed
    BatchTooLarge,
    /// An internal storage error occurred
    InternalError,
    /// The operation is not permitted
    PermissionDenied,
    /// The iteration limit is invalid (zero or too large)
    InvalidLimit,
}
```

### Method Specifications

#### Basic Operations

##### `get(namespace: Vec<u8>, key: Vec<u8>) -> Result<Option<Vec<u8>>, StorageError>`

Retrieves a value by key from the specified namespace.

- **Parameters**:
  - `namespace`: The namespace to query (max 256 bytes)
  - `key`: The key to look up (max 1024 bytes)
- **Returns**: `Some(value)` if the key exists, `None` otherwise
- **Errors**:
  - `KeyTooLarge`: key exceeds 1024 bytes
  - `NamespaceTooLarge`: namespace exceeds 256 bytes
  - `InternalError`: storage backend failure

##### `set(namespace: Vec<u8>, key: Vec<u8>, value: Vec<u8>) -> Result<(), StorageError>`

Stores a key-value pair in the specified namespace. If the key already exists, the value is updated.

- **Parameters**:
  - `namespace`: The namespace to store in (max 256 bytes)
  - `key`: The key to store (max 1024 bytes)
  - `value`: The value to store (max 65536 bytes)
- **Returns**: `Ok(())` on success
- **Errors**:
  - `KeyTooLarge`: key exceeds 1024 bytes
  - `ValueTooLarge`: value exceeds 65536 bytes
  - `NamespaceTooLarge`: namespace exceeds 256 bytes
  - `StorageFull`: storage capacity exceeded
  - `InternalError`: storage backend failure

##### `delete(namespace: Vec<u8>, key: Vec<u8>) -> Result<bool, StorageError>`

Deletes a key-value pair from the specified namespace.

- **Parameters**:
  - `namespace`: The namespace to delete from (max 256 bytes)
  - `key`: The key to delete (max 1024 bytes)
- **Returns**: `true` if the key existed and was deleted, `false` if the key did not exist
- **Errors**:
  - `KeyTooLarge`: key exceeds 1024 bytes
  - `NamespaceTooLarge`: namespace exceeds 256 bytes
  - `InternalError`: storage backend failure

##### `exists(namespace: Vec<u8>, key: Vec<u8>) -> Result<bool, StorageError>`

Checks if a key exists in the specified namespace.

- **Parameters**:
  - `namespace`: The namespace to check (max 256 bytes)
  - `key`: The key to check (max 1024 bytes)
- **Returns**: `true` if the key exists, `false` otherwise
- **Errors**:
  - `KeyTooLarge`: key exceeds 1024 bytes
  - `NamespaceTooLarge`: namespace exceeds 256 bytes
  - `InternalError`: storage backend failure

#### Batch Operations

##### `batch_get(namespace: Vec<u8>, keys: Vec<Vec<u8>>) -> Result<Vec<Option<Vec<u8>>>, StorageError>`

Retrieves multiple values by keys from the specified namespace.

- **Parameters**:
  - `namespace`: The namespace to query (max 256 bytes)
  - `keys`: List of keys to look up (max 100 keys, each max 1024 bytes)
- **Returns**: List of values in the same order as keys, `None` for non-existent keys
- **Errors**:
  - `KeyTooLarge`: any key exceeds 1024 bytes
  - `NamespaceTooLarge`: namespace exceeds 256 bytes
  - `BatchTooLarge`: more than 100 keys requested
  - `InternalError`: storage backend failure

##### `batch_set(namespace: Vec<u8>, entries: Vec<KeyValue>) -> Result<(), StorageError>`

Stores multiple key-value pairs atomically in the specified namespace.

- **Parameters**:
  - `namespace`: The namespace to store in (max 256 bytes)
  - `entries`: List of key-value pairs to store (max 100 entries)
- **Returns**: `Ok(())` on success
- **Errors**:
  - `KeyTooLarge`: any key exceeds 1024 bytes
  - `ValueTooLarge`: any value exceeds 65536 bytes
  - `NamespaceTooLarge`: namespace exceeds 256 bytes
  - `BatchTooLarge`: more than 100 entries
  - `StorageFull`: storage capacity exceeded
  - `InternalError`: storage backend failure

##### `batch_delete(namespace: Vec<u8>, keys: Vec<Vec<u8>>) -> Result<u32, StorageError>`

Deletes multiple key-value pairs from the specified namespace.

- **Parameters**:
  - `namespace`: The namespace to delete from (max 256 bytes)
  - `keys`: List of keys to delete (max 100 keys, each max 1024 bytes)
- **Returns**: Number of keys that were actually deleted
- **Errors**:
  - `KeyTooLarge`: any key exceeds 1024 bytes
  - `NamespaceTooLarge`: namespace exceeds 256 bytes
  - `BatchTooLarge`: more than 100 keys
  - `InternalError`: storage backend failure

#### Iteration

##### `iter_keys(namespace: Vec<u8>, prefix: Vec<u8>, limit: u32) -> Result<Vec<Vec<u8>>, StorageError>`

Lists keys in the namespace that start with the given prefix.

- **Parameters**:
  - `namespace`: The namespace to iterate (max 256 bytes)
  - `prefix`: Key prefix to filter by (max 1024 bytes)
  - `limit`: Maximum number of keys to return (1-1000)
- **Returns**: List of matching keys
- **Errors**:
  - `NamespaceTooLarge`: namespace exceeds 256 bytes
  - `KeyTooLarge`: prefix exceeds 1024 bytes
  - `InvalidLimit`: limit is 0 or exceeds 1000
  - `InternalError`: storage backend failure

##### `iter_values(namespace: Vec<u8>, prefix: Vec<u8>, limit: u32) -> Result<Vec<Vec<u8>>, StorageError>`

Lists values for keys that start with the given prefix.

- **Parameters**:
  - `namespace`: The namespace to iterate (max 256 bytes)
  - `prefix`: Key prefix to filter by (max 1024 bytes)
  - `limit`: Maximum number of values to return (1-1000)
- **Returns**: List of values for matching keys
- **Errors**:
  - `NamespaceTooLarge`: namespace exceeds 256 bytes
  - `KeyTooLarge`: prefix exceeds 1024 bytes
  - `InvalidLimit`: limit is 0 or exceeds 1000
  - `InternalError`: storage backend failure

##### `iter_entries(namespace: Vec<u8>, prefix: Vec<u8>, limit: u32) -> Result<Vec<KeyValue>, StorageError>`

Lists key-value pairs for keys that start with the given prefix.

- **Parameters**:
  - `namespace`: The namespace to iterate (max 256 bytes)
  - `prefix`: Key prefix to filter by (max 1024 bytes)
  - `limit`: Maximum number of entries to return (1-1000)
- **Returns**: List of key-value pairs for matching keys
- **Errors**:
  - `NamespaceTooLarge`: namespace exceeds 256 bytes
  - `KeyTooLarge`: prefix exceeds 1024 bytes
  - `InvalidLimit`: limit is 0 or exceeds 1000
  - `InternalError`: storage backend failure

#### Namespace Management

##### `clear_namespace(namespace: Vec<u8>) -> Result<u32, StorageError>`

Deletes all key-value pairs in the specified namespace.

- **Parameters**:
  - `namespace`: The namespace to clear (max 256 bytes)
- **Returns**: Number of entries that were deleted
- **Errors**:
  - `NamespaceTooLarge`: namespace exceeds 256 bytes
  - `PermissionDenied`: clearing this namespace is not allowed
  - `InternalError`: storage backend failure

##### `namespace_size(namespace: Vec<u8>) -> Result<u64, StorageError>`

Returns the total size in bytes used by the namespace.

- **Parameters**:
  - `namespace`: The namespace to measure (max 256 bytes)
- **Returns**: Total bytes used by keys and values in the namespace
- **Errors**:
  - `NamespaceTooLarge`: namespace exceeds 256 bytes
  - `InternalError`: storage backend failure

### Wire Format

All messages follow the CKB Script IPC wire format (see README.md):

**Request Packet:**
```
[version: VLQ] [method_id: VLQ] [length: VLQ] [payload: JSON]
```

**Response Packet:**
```
[version: VLQ] [error_code: VLQ] [length: VLQ] [payload: JSON]
```

Method IDs are assigned automatically by the service macro based on method order:

| Method | Method ID |
|--------|-----------|
| `get` | 0 |
| `set` | 1 |
| `delete` | 2 |
| `exists` | 3 |
| `batch_get` | 4 |
| `batch_set` | 5 |
| `batch_delete` | 6 |
| `iter_keys` | 7 |
| `iter_values` | 8 |
| `iter_entries` | 9 |
| `clear_namespace` | 10 |
| `namespace_size` | 11 |

### Size Limits

| Resource | Limit |
|----------|-------|
| Namespace | 256 bytes |
| Key | 1024 bytes |
| Value | 65536 bytes (64 KB) |
| Batch size | 100 entries |
| Iteration limit | 1000 entries |

## Rationale

### Why Namespace-Based Isolation?

The namespace parameter provides logical isolation between different clients or use cases:

1. **Multi-tenant Support**: Different scripts can share a storage service without conflict
2. **Access Control**: Implementations can enforce access policies per namespace
3. **Organization**: Data can be logically grouped for management and cleanup

### Why Batch Operations?

Batch operations are provided for efficiency:

1. **Reduced Overhead**: Multiple operations in a single IPC call reduces communication overhead
2. **Atomicity**: `batch_set` provides atomic multi-key writes
3. **Efficiency**: Backend can optimize batch operations

### Why Prefix-Based Iteration?

Prefix-based iteration enables hierarchical key organization:

1. **Hierarchical Keys**: Keys like `user:123:name`, `user:123:email` can be iterated with prefix `user:123:`
2. **Efficient Scanning**: No need to load all keys into memory
3. **Pagination**: Limit parameter allows processing large datasets in chunks

### Why Size Limits?

Size limits are necessary for:

1. **Resource Protection**: Prevents unbounded memory usage
2. **DoS Prevention**: Limits attack surface for resource exhaustion
3. **Practical Usage**: Encourages proper data design and chunking

## Backwards Compatibility

This is a new interface standard. There are no backwards compatibility concerns.

Future versions of this interface should:
- Only add new methods, not modify existing ones
- Use new method IDs for new functionality
- Maintain wire format compatibility
- Consider backward-compatible size limit increases

use alloc::vec::Vec;

### Usage Example

```rust
use ckb_kv_storage_interface::{KvStorage, KvStorageClient, KeyValue, StorageError};
use ckb_script_ipc_common::spawn::spawn_server;

// Start the storage service
let (read_pipe, write_pipe) = spawn_server(0, Source::CellDep, &[])?;

// Create client
let mut client = KvStorageClient::new(read_pipe, write_pipe);

// Define namespace
let namespace = b"my_app".to_vec();

// Set a value
client.set(namespace.clone(), b"user:1:name".to_vec(), b"Alice".to_vec())?;

// Get a value
let name = client.get(namespace.clone(), b"user:1:name".to_vec())?;
assert_eq!(name, Some(b"Alice".to_vec()));

// Batch set multiple values
let entries = vec![
    KeyValue { key: b"user:1:email".to_vec(), value: b"alice@example.com".to_vec() },
    KeyValue { key: b"user:1:age".to_vec(), value: b"30".to_vec() },
];
client.batch_set(namespace.clone(), entries)?;

// Iterate over all user:1 keys
let keys = client.iter_keys(namespace.clone(), b"user:1:".to_vec(), 100)?;
// keys = ["user:1:age", "user:1:email", "user:1:name"]

// Check namespace size
let size = client.namespace_size(namespace.clone())?;
```

## Security Considerations

### Namespace Isolation

Implementations MUST ensure that:
- Operations on one namespace cannot affect another namespace
- Namespace boundaries are strictly enforced
- Cross-namespace attacks (e.g., via key overlap) are not possible

### Input Validation

All implementations MUST validate:
- Input lengths against size limits
- Key and namespace formats
- Batch sizes before processing

### Resource Exhaustion

Implementations SHOULD:
- Implement rate limiting per namespace
- Monitor and cap total storage usage
- Provide fair resource allocation among clients

### Data Confidentiality

Implementations SHOULD consider:
- Encryption at rest for sensitive data
- Access control mechanisms for namespaces
- Audit logging for sensitive operations

### Denial of Service

Implementations MUST protect against:
- Large batch operations consuming excessive resources
- Iteration operations scanning entire storage
- Rapid create/delete cycles
